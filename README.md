# puzzle_loop

[puzzle-pipes.com](https://www.puzzle-pipes.com/)（接水管 / Net）的抓题、推理求解与游戏还原。

## 文件

| 文件 | 作用 |
|---|---|
| `get_puzzle.py` | 抓取题面（题面数据就在页面 HTML 源码里），保存到 `puzzles/` |
| `solver.py` | 求解器：R1–R8 规则推理，可选 DFS + 回溯 |
| `gui.py` | 图形界面：回放每一步推理（进度条拖动），支持手动挑选候选形状辅助推理 |
| `game.py` | 还原的游戏：点击旋转水管，自动判定连通与解开 |
| `extension/` | 浏览器插件：把同一套规则推理应用到 puzzle-pipes.com 真实页面上 |

## 用法

```bash
python get_puzzle.py          # 随机抓一道 10x10（?size=3）
python get_puzzle.py 5        # 抓更大盘面
python get_puzzle.py 3 6672132  # 按题号抓取（题号在对应尺寸下才有效）
python get_puzzle.py wrap 10  # 抓 10x10 Wrap（环形）；也可用 10x10-wrap 或 size 序号 13
python solver.py              # 推理求解 puzzles/ 里最新一道
python solver.py --search     # 规则传播后用 DFS + 回溯继续求解
python solver.py --search --strategy degree puzzles/xxx.txt
                               # 指定搜索策略（first/mrv/degree/edge）
python solver.py --compare puzzles/xxx.txt
                               # 对比四种策略的节点、回溯和耗时
python gui.py                 # 步骤回放界面（加载 puzzles/ 里最新一道）
python gui.py 6672132         # 按题号加载（默认 10x10；本地已有直接用，
                              # 否则联网抓取并保存到 puzzles/）
python gui.py 5 6180259       # 按尺寸+题号加载
python game.py                # 玩还原的游戏
python test_wrap.py           # wrap 环形求解的回归测试
```

## 数据格式

每个谜题保存为 `puzzles/` 下的 txt 文件（文件名含尺寸、题号与抓取时间）：

- `task_hex`：每格一个十六进制字符（行优先），是 4-bit 管道掩码
- `hashed_solution: md5(task_hex + 旋转串)`，游戏官方的胜利判定，可用于校验
- `wrap: 0/1`：是否为环形（Wrap）题面，`solver.py`/`gui.py`/`game.py` 据此切换几何
- 掩码位含义（对照游戏源码 `dc=[1,0,-1,0], dr=[0,-1,0,1]` 确认）：
  **1=右 2=上 4=左 8=下**
- 注意：**题号在对应尺寸下才有效**（同一题号在不同尺寸下是不同的题）。
- 每点一次水管 = 4 位左循环移位 `((m<<1)&15) | (m>>3)`；直线型（5/10）周期为 2，
  官方校验时把转 2 次记 0、转 3 次记 1（规范化为最小等效旋转）

## 求解模型（solver.py）

按"格子状态 + 连接状态"两层结构做纯推理：

- **格子状态网格**：每格记录"还可能的形状集合"（该格掩码旋转出的所有形状），
  集合只剩 1 个即为**确定格子**
- **连接状态数组**：相邻格子之间的边，三态 = 确定需要连接 / 确定不连接（墙）/ 未确定

推理规则（每应用一条记为一步）：

- **R1 边界排除**：棋盘外的方向一律是墙（外圈的 T 型、直线型由此直接确定）
- **R2 确定格子推边**：确定格子的开口方向 → 需要连接；非开口方向 → 墙
- **R3 边推格子**："需要连接"的边排除没有对应开口的形状，"墙"排除有开口的形状
- **R4 多数一致推边**：未确定格子若剩余所有形状都朝某方向开口 → 该边需要连接；
  都不开口 → 该边是墙

全局规则（最终解是一棵生成树：全连通、无环、恰 V-1 条连接）：

- **R5 成环检查**：确定连接边必须构成森林（并查集），围成闭环即矛盾
- **R6 孤岛检查**：把"需要连接∪未确定"的边洪泛，分成多块即矛盾
- **R7 唯一出口**：某连通块通向外界的未确定边只剩一条 → 该边必连
- **R8 预算/容量**：树需要恰"块数-1"条跨块边，恰好只剩这么多条时全部必连；
  块内确定边已满 c-1 条（内部已是树）→ 块内剩余未知边全是墙
- **R9 环必须断开**（仅 wrap）：环面上每行的横边、每列的竖边各自成环，
  生成树不能整圈取连接 → 某行/列只剩一条未定而其余全连接时，该边必是墙

默认纯规则模式不使用搜索、枚举或回溯；推理不动了就停在那里。

### 搜索式求解（`solver.py --search`）

在 R1–R9 规则传播达到不动点后，搜索器选择一个未确定变量，尝试候选值并
递归传播；出现局部冲突、成环或孤岛时恢复检查点并回溯。搜索成功后会验证
无悬空开口、全盘连通以及（若题面提供）官方 MD5。

`--strategy` 可选：`first` 按行优先取第一个未确定格；`mrv` 取候选最少的格；
`degree` 取未知邻边最多的格；`edge` 直接对支持数最少的未知边做二叉分支。
`--compare` 会在同一题面上运行四种策略，输出节点数、决策数、矛盾/回溯数、
最大深度和耗时，便于用不同尺寸的题目做基准。

### wrap（环形）模式

网站首页把 Wrap 题挂在 `?size=10..16`（普通 `0..6`，`+10` 即 wrap），
页内 `wrap:1` 标明是环形。抓题用 `python get_puzzle.py wrap 10`（或
`10x10-wrap`、size 序号 `13`），保存的 txt 里带 `wrap: 1`。

环形棋盘左右相接、上下相接（torus），**没有边界墙**。求解器在 `wrap=True`
时把所有方向都当作有边、坐标一律取模，`board_check` 的连通洪泛也按环面走。

关键差别：由于没有边界，**R1 开局一条也推不动**，纯规则模式在 wrap 上会
零推导；必须用 `--search`。搜索的 `mrv` 策略会优先挑候选最少的格子，
在 wrap 开局通常先落到直线型（剩 2 种）或十字型（剩 1 种）的格子上，收敛很快。
生成树性质（V-1 条连接、无环、全连通）在环面上仍成立，另加 wrap 专属 R9。

实测 4/5/7/10/15/20/25 wrap 多道随机题都能搜索解出且官方 MD5 通过
（`python test_wrap.py` 会验证几何、R9 与真实题面的生成树性质）。

## gui.py 的手动操作

- **左键点未确定格子**：挑选它的一个候选形状（格子里列出的灰色字形之一），
  之后推理自动继续；再点同格 = 轮换到下一个候选
- **「自动推理」勾选框（默认开）**：关闭后左键挑选只记录选择、不跑任何规则，
  方便自己逐格手推观察；此时点 **「执行推理」** 按钮可随时手动推一轮到不动，
  若推出矛盾会自动回退到推理前并提示原因（成环/孤岛）
- **右键点格子**：撤销该格的手动挑选（它引发的推理一并回退）
- **「撤销全部手动」按钮**：回到纯推理状态
- 挑选若推出**矛盾**：自动回滚；若尝试时不存在任何人工假设，
  则该形状可确定排除（记作「手动排除」步），随后推理继续——
  反复左键轮换即可逐个排除候选，直到剩下正确形状。
  挑选后的自动推理包含全局规则 R5–R8，矛盾原因会明确标出
  （局部冲突 / **成环** / **孤岛**）
- 全部格子确定后状态栏会显示官方 md5 校验是否通过

## 浏览器插件（extension/）

把 solver 的同一套推理（R1–R9 规则推理 + DFS/回溯搜索）直接应用到网站真实棋盘，
普通与 **wrap（环形）** 模式都支持。

**安装**：Chrome 打开 `chrome://extensions` → 右上角开启「开发者模式」→
「加载已解压的扩展程序」→ 选择本仓库的 `extension/` 目录 →
打开 https://www.puzzle-pipes.com/ ，页面左上角出现「🧩 规则推理助手」面板。

**原理**：页面棋盘是纯 DOM——每格 `div.cell` 的 class 里
`pipe{N}` = 题面掩码（永不变化）、`cell-{N}` = 当前旋转状态
（普通点击 −1 mod 4，Ctrl+点击 +1 mod 4，当前掩码 = 题面掩码左移循环 N 次）。
插件直接读这些 class 得到题面与现状，推理后向格子派发合成鼠标事件来旋转，
所以走的是和真人点击完全相同的游戏代码路径，官方计时/判定照常工作。
wrap 模式由棋盘上的 `.wrapH`/`.wrapV`（接缝标记）自动识别。

**面板**：

- **「🔍 一键求解」按钮**：对当前盘面跑搜索（DFS + 规则传播/R1–R9），
  求出完整解后**直接把整盘转到位**（走真实点击，官方判定照常触发）；wrap
  模式开局没有边界墙、规则一步都推不动，用这个按钮即可直接解出。
  手动摆过的格子当作人工假设；要是摆错了导致无解，会提示并可用「后退」撤销。
  填充作为一整批进入历史，可一次撤销
- **「自动推理」勾选框**
  - 勾上：立即在后台做一轮 R1–R9 推理；出错（成环/孤岛/连接冲突）或推不下去就停
  - 有建议时，需要旋转的格子**橙色常亮**标出，主按钮变为「确认填充 N 格」，
    **再次点击才真正填充**；填充后自动继续下一轮
  - 取消勾选：什么都不做（并清掉未确认的建议标记）
- **「显示未确认区域（蓝色常亮）」勾选框**：蓝色常亮标出推理**尚未确定**的格子
  （每轮推理后更新），一眼看出还剩哪些区域没确认，方便手推；换题后自动清空
- **「重新推理」**：手动摆过格子后随时再推一轮
- **「后退」**：有未确认建议时 = 取消建议；否则撤销上一次填充（整批还原），
  「一键求解」的整盘填充也可用它一步撤销
- **推理出错标记**：出错时把**从本轮推理开始到出错为止涉及过的所有格子**
  （poss 变化、被设过的边的两端、人工假设格、成环/孤岛相关格）用**红色常亮**标出，
  方便定位是哪个手工摆放或哪步推理引出的矛盾
- **手动摆放永远不会被擦掉**：旋转状态 ≠ 0 的格子一律当作人工假设参与推理，
  建议填充只落在未被手动摆过的格子上，且按当前盘面算增量点击
- 状态栏实时显示"已确定 X/Y 格"；全部确定时附盘面校验结果
- 插件状态不落盘：换题/刷新后历史自动清空，一切以页面现状为准

**测试**：`solver.js` 是 `solver.py` 的 JS 移植，离线用 node 对拍过——

```bash
node extension/test_solver.js    # puzzles/ 全部题面：搜索解出 + 官方 md5（含 wrap）
node extension/test_content.js   # 模拟 DOM：盘面扫描 + 一键求解真的把盘面摆成解
```
